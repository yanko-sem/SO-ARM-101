# Contribuer au projet SO-ARM 101

Merci de votre intérêt pour ce projet de robotique éducative.

Ce dépôt propose une chaîne complète pour apprendre la robotique, l’apprentissage par imitation et le déploiement autonome avec deux bras SO-ARM 101, LeRobot, deux caméras et un modèle ACT.

## Types de contributions bienvenues

Vous pouvez contribuer de plusieurs manières :

- signaler un bug ;
- proposer une amélioration des scripts ;
- améliorer les guides pédagogiques ;
- corriger une erreur ou une imprécision ;
- proposer une traduction ;
- ajouter des schémas, images ou vidéos ;
- documenter une nouvelle tâche robotique ;
- partager un retour d’expérience en classe ou en atelier.

## Avant de contribuer

Avant de proposer une modification, vérifiez si elle respecte les principes du projet :

1. **Clarté pédagogique**  
   Le projet doit rester compréhensible pour des enseignants, étudiants et débutants motivés.

2. **Robustesse technique**  
   Toute modification des scripts doit éviter les régressions, préserver les sécurités existantes et ne pas modifier inutilement le comportement du robot.

3. **Reproductibilité**  
   Les étapes doivent pouvoir être répétées sur une installation propre.

4. **Sécurité**  
   Les changements ne doivent pas supprimer les garde-fous : retour repos, arrêt d’urgence, contrôle caméra, contrôle série, cohérence dataset/déploiement.

## Signaler un problème

Lorsqu’un problème est signalé, merci d’indiquer si possible :

- le script concerné ;
- la phase concernée ;
- le système utilisé ;
- le matériel utilisé ;
- le message d’erreur complet ;
- les étapes permettant de reproduire le problème ;
- ce qui était attendu ;
- ce qui s’est réellement passé.

## Proposer une modification

Pour proposer une modification :

1. créez une branche dédiée ;
2. effectuez une modification ciblée ;
3. testez le script ou le guide concerné ;
4. décrivez clairement le changement ;
5. expliquez pourquoi il est utile ;
6. indiquez les risques éventuels de régression.

## Style attendu

Les contributions doivent privilégier :

- des scripts lisibles ;
- des commentaires utiles ;
- des changements ciblés ;
- des messages d’erreur compréhensibles ;
- une documentation pédagogique ;
- une cohérence forte entre les phases.
